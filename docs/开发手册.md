## 一、项目定位

- **是什么**：生鲜批发 B2B 经营系统「鲜配订货」——录单 → 采购 → 分拣 → 打印 → 收款 → 对账 → 报表。
- **给谁用**：首发商家A（本地蔬菜批发配送商）；终局白牌多租户 SaaS 卖同行。
- **产品边界**：精简版。竞品买方核心诉求是"录单 → 分拣 → 打单"链路，不做全家桶。

## 二、系统架构（一图流）

```
┌─ 商家管理端 web-admin ──── Vue3+Vite6+ElementPlus，发布于静态托管根路径
├─ 网页商城 web-mall ──────── 单文件 H5，发布于 /mall/
├─ 微信小程序 miniprogram ─── 原生小程序（正式 AppID wx0000000000000000，个人主体）
│      三端数据访问：读 = @cloudbase/js-sdk app.rdb()（postgREST 风格 eq/in/lte/order/range/rpc，
│                    没有 .where/.orderBy/.count）；写 = 网关 REST restWrite()（统一通道，见坑 7）
├─ 云函数 ai ──────────────── LLM 录单解析（text/image/audio 三模）
│      文本/语音：DeepSeek deepseek-flash；图片：智谱 glm-4.5v（9/12 A/B 胜出切主通道）
│      语音转写：腾讯云一句话识别（TC3 签名手写）
│      网关入口：https://{env}.service.tcloudbase.com/ai（匿名，小程序直调）
├─ PostgreSQL ────────────── 15 张业务表 + ff_actor()/ff_customer_level() + 28 条 RLS 策略
└─ 环境与托管 ─────────────── CloudBase freshflow-ENV_ID（上海，体验版，免费至 2027-03-10）
```

**多租户铁律**：所有业务表带 `tenant_id`；登录身份由 `ff_actor()`（SECURITY DEFINER）判定 = admin_user / customer_user 的 uid 匹配 `auth.uid()`；RLS 策略强制隔离（员工 = 本租户全权，店家 = 本公司 + 商城可见商品）。**卖同行 = INSERT 一行 tenant + 开一个管理员账号，代码零改动。**

**权限模型三层**：系统制作者（我，平台层）→ 菜贩子（merchant_a，租户管理员 boss）→ 店家（customer_user，只看自己）。admin_user 预留 boss / manager / operator 三档。

## 四、数据模型（15 表速查）

| 表 | 用途 | 关键点 |
|---|---|---|
| tenant | 租户（白牌配置：商城名 / 系统名 / 主题） | 卖同行加行即开张 |
| admin_user / customer_user | 员工 / 客户子账号 | uid=auth.uid()；role: boss/manager/operator |
| goods_category / goods | 分类 / 商品 | 别名数组（识别匹配）、weigh_type（none=标品打 N 张贴纸）、description 详情、stock_qty/stock_alert 库存 |
| customer / customer_address / customer_visible_category | 客户 / 地址 / 可见分类 | 等级、结算方式、credit_limit、overdue_days |
| price | 报价 | scope=type/customer，valid_from 历史留痕；取价链 = 专属→等级→基准 |
| order_main / order_item | 订单头 / 明细 | 状态机 draft→confirmed→sorting→ready→shipped→done/void；下单+实拣双数量、edit_log 留痕 |
| sort_record / print_log | 分拣流水 / 打印流水 | 秒级时间戳、补打链 |
| payment_ledger | 往来账 | receivable/received，balance_after 快照 → 账期锁单 |
| purchase_order(+item) | 采购 | need_qty 聚合、bought_qty/cost_price 到货回填 → 喂最近价与成本利润 |
| inventory_log | 库存流水 | delta 正入负出，reason: purchase_in/ship_out/adjust |
| op_log | 操作日志 | 强制放行、收款等敏感动作 |

金额口径（详见 `STATE_AND_AMOUNT.md`）：出货单金额 = Σ 实拣数量 × 实拣价；订单金额 = Σ 下单量 × 下单价。

**迁移纪律**：DDL 全走 `managePgDatabase execute`（applyMigration 静默失败不可用）；迁移事实源 = `database/migrations/` 本地文件（已应用 4 份：auth_foundation / purchase / goods_description / inventory）。

## 六、部署与运维

**本地开发**：`cd D:\FreshFlow\web-admin && npm run dev` → localhost:5273（或双击启动后台.bat）。⚠️ localhost 真实登录被拒（体验版无自定义安全域名），本地只看界面，验证登录和数据走线上。

**发布后台**：`npm run build` → 把 `web-admin\dist` 上传到静态托管根路径（ZCode 用 manageHosting；CLI 用 `tcb hosting deploy`；或控制台手动上传）。商城同理上传 `web-mall` 到 `/mall/`。

**发布小程序**：devtools 打开 miniprogram → 右上角「上传」（在编辑器工具栏，不在项目列表面板）→ 后台「版本管理」→ 设为体验版 → 成员管理加体验成员 → 扫体验二维码。**每次重新上传都要重新"选为体验版"**（二维码不变，手机自动更到新版）。正式发布 = 备案通过后提审（现在不提）。

**发布云函数**：改 `cloudfunctions\ai\index.js` 后整体部署；部署前先 `getFunctionDetail` 对比线上版本（多窗口并行防覆盖）。

**给客户开号标准流程**：managePermissions createUser（用户名 = 客户拼音、密码 = 首字母大写+小写+数字）→ 拿 uid → `INSERT INTO customer_user (tenant_id, customer_id, uid, username, password_hash, display_name, status) VALUES (1, <客户id>, '<新uid>', '<用户名>', 'managed-by-cloudbase-auth', '<显示名>', 'active')` → 把网址+账号密码发给客户。员工则 INSERT admin_user。

**重置密码**：managePermissions updateUser(uid=..., password='新密码')。

**常用运维 SQL**：见 `docs\DB速查卡.md`（控制台三件套 + 三条救命 SQL + 月度备份流程）。清测试流水 SQL 模板：

```sql
DELETE FROM sort_record; DELETE FROM print_log; DELETE FROM payment_ledger;
DELETE FROM order_item;  DELETE FROM order_main;  DELETE FROM inventory_log;
DELETE FROM purchase_order_item; DELETE FROM purchase_order;
```

**恢复库存 / 采购菜单**：`MainLayout.vue` 的 `HIDE_MODULES_FOR` 数组删掉 'merchant_a' → 重新构建发布。

## 七、失败提示设计原则

**全系统零静默失败**（9/12 定档）：
- 商城：登录失败页内红字具体原因（👁 明文切换 / 加载态）；下单失败弹窗带原因 + 5 秒倒计时；401 自动 refreshOnce 续期重试一次，彻底失效清会话回登录页。
- 后台：保存类操作写后回读比对；update 加 `.select(id)` 0 行守卫；批量写逐条 + 回查；restWrite 非 2xx 抛真实错误文本。
- 识别类：AI 产物一律进人工确认（三态匹配 / 确认弹窗），不直接落单。

## 八、平台坑清单（每条都真实踩过，勿再踩）

1. **applyMigration 静默失败**：返回 success 但不落库 → DDL/DML 全走 execute 通道；迁移事实源 = `database/migrations/` 本地文件。
2. **Auth 域名**：登录只认 `api.tcloudbasegateway.com`；旧域 tcb-api.tencentcloudapi.com 返回 4043 假"密码错误"。
3. **体验版限制**：不能加自定义安全域名（localhost 真实登录被拒）；授权用户上限 3 个；envDomainManagement 被拒；**函数日志检索不可用**（listFunctionLogs 报"升级开发者工具"）→ 验链路用 `manageFunctions invokeFunction` 直调（~1.5s）二分定位"函数内部 vs 网关"。
4. **密码策略**：≥3 类字符；点号不算特殊类；用"首字母大写+小写+数字"。
5. **时区**：一切"今天"用 `localToday()`；toISOString 是 UTC，北京时间 0-8 点差一天。
6. **写入必须带 `Prefer: return=representation`** 才返回新行，且"拿 id"场景必须做按唯一键回查兜底（POST 不保证返回 representation）。
7. **js-sdk 写链路在本环境不可靠**（update 静默 0 行 / insert 不落库，多轮实证）→ **写全走 restWrite 网关直连，js-sdk 只读**；会话 2h 过期问题随 restWrite 现取 token 自然规避。
8. **Git Bash curl 发中文 = GBK 乱码**（两次入库事故）→ 测试体用 `printf` 写 UTF-8 文件 + `--data-binary @file`，或 MCP 数据库层。
9. **RLS 函数**：ff_actor() 被策略依赖不能 DROP 改签名；加字段用新辅助函数（ff_customer_level 先例）。
10. **多窗口并行**：改 services.js / SmartEntry / SortBoard / MainLayout 前必读磁盘最新版 + git diff；冲突以磁盘为准；`ai\test\` 是并行窗口活跃区勿动。
11. **小程序 app.json 必须声明 `permission.scope.record`**，缺它真机录音静默失败（devtools 里看不出来）。
12. **TC3 签名**：canonicalHeaders 尾换行后必须再加分隔换行（官方数组 join 写法自带双换行），少一个即 SignatureFailure；fetch 不要手动设 Host 头。
13. **同声传译插件**：个人主体 / 无匹配 IT 类类目 = 永久关闭，别再试插件路线；语音走自建 ASR 链。
14. **Mimosa 钩子**：拦 bash heredoc 写源码、动态路径 open 的 .py、变量 URL fetch → 用 Write 工具 + 字面量 URL。
15. **正则批量改代码必须复核 await 语义**（po_id 孤儿单事故）；**表单字段联动切换必须显式重置依赖字段**（报价脏数据事故）。

## 十、验收基线

- **M1（已达成）**：任一输入方式（手工 / 文本 / 图片 / 语音 / 客户自助）→ 订单 → 打印 ≤3 分钟；商城下单后台可见；账期锁单生效；对账 / 日报可见。
- **M2（待硬件）**：过称联动 → 打单 ≤3 分钟（等秤型号）。
