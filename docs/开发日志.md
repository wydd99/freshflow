## 一、项目缘起

起点：一段 31 分钟的竞品「鲜橙供应链」销售演示视频（`桌面\SVID_20260909_175758_1.mp4`）。处理方式：291 帧加密抽帧逐帧分析 + 8563 字语音转写，提炼出 21 条真实需求（沉淀在 `docs\REQS.md`）。

核心结论：**买方嫌竞品太复杂，真实诉求是"录单 → 分拣 → 打单"这条精简链路**。因此本项目定位为精简版，不做全家桶；效果质量优先于功能数量。

- **首发用户**：商家A（本地蔬菜批发配送商）
- **终局目标**：白牌多租户 SaaS 卖同行（数据库层原生多租户，加租户即开张）
- **开发周期**：2026-09-10 ~ 09-12 主体功能收官（3 天，多窗口并行开发），9/13 起进入交付陪跑期

## 三、关键事故复盘（现象 → 根因 → 修复 → 沉淀）

> 每一条都真实踩过。完整平台坑清单（含环境层）见《开发手册》第八节，这里记的是**业务级事故**。

13. **云函数常量声明被编辑误删**（9/15）
    - 现象：向导接口报 "GW is not defined"。
    - 根因：Edit 工具的 old_string 整块替换把相邻的 `const ENV_ID/GW` 声明一起顶掉了，替换文本没带回。
    - 修复：部署前实测发现，补回声明。
    - 沉淀：**整块替换编辑后必须 grep 校验相邻常量/导入完整性**；所幸部署前探活抓住了它。

14. **建号全撞配额墙（认知事故）**（9/14-15，用户纠正）
    - 现象：建任何新号都报"超过配额限制"，一度以为要开新环境/升套餐。
    - 根因：CreateUser 有 `Type` 参数（internal/external），不传默认内部；内部仅 3 个，外部不限量。所有建号通道（含 useradmin）从未传过该参数。
    - 修复：全部通道切 externalUser；内部 3/3 故意占满防误注册。
    - 沉淀：**平台配额类"硬墙"先查文档找维度（类型/来源/入口），别急着花钱扩容**——用户一句"外部名额不限"点破了整个困局。

15. **测试脚本中文乱码污染租户数据**（9/15-16）
    - 现象：商家B租户出现两个乱码分类名。
    - 根因：5.3 窗口测试脚本写请求时中文编码坏（Git Bash 老坑的新变体：不只 curl 直发，脚本内联中文字符串也会坏）。
    - 修复：确认无商品挂载后删除；分类清单恢复。
    - 沉淀：**凡测试体含中文，必须写文件校验编码后再发，或走 MCP 数据库层**。

1. **收款假成功**（9/12）
   - 现象：页面弹"登记成功"，数据库里没有收款记录，欠款不降。
   - 根因：旧 unwrap 通道写入静默丢（浏览器 js-sdk rdb 写链路在本环境不可靠）。
   - 修复：登记收款改 restWrite 网关直连 + 写后回查校验；用户那笔 ¥39.60 由运维手工补录。
   - 沉淀：**全系统 34 处写调用最终全部切网关 REST**（js-sdk 只保留读），"零静默失败"成为设计原则。

2. **报价脏数据"客户专属 · A"**（9/12）
   - 现象：报价列表出现scope_value 存了等级"A"但 scope 是 customer 的非法行。
   - 根因：新增价格弹窗从"按等级"切到"按客户"时，旧选中的"A"残留在 scopeValue。
   - 修复：onScopeSwitch 强制重置 + 保存前校验 customer_id 必须为数字 + 脏数据清理。
   - 沉淀：表单字段联动，切换时必须显式重置依赖字段。

3. **店家进后台越权洞**（9/12，用户发现，严重级）
   - 现象：客户子账号（customer_a）能登录商家管理后台。
   - 根因：后台登录页未校验账号身份类型。
   - 修复：三端登录身份校验（customer 只能进商城，admin 才能进后台）+ 价格 RLS 收紧（`ff_customer_level()` + `p_price_cust`，店家只见自己档价格行）。
   - 沉淀：**前端隐藏 ≠ 权限**，隔离必须在数据库层（RLS）兜底。

4. **商城下单后双方都看不到**（9/12）
   - 现象：客户下单成功，"我的订单"和商家端都没有。
   - 根因：POST 不带 `Prefer: return=representation` 时返回 201 空体，拿不到订单 id → 明细挂不上 → 整单不可见。
   - 修复：insert 全部加 Prefer 头 + 按唯一单号回查兜底。
   - 沉淀：**凡是"POST 后要拿 id"的写入，必须做拿不到返回值的兜底回查**。

5. **采购单生成报 po_id not-null**（9/12）
   - 现象：生成采购单报错，但主单已落库（产生孤儿单）。
   - 根因：上一轮正则批量替换把 5 处 `const created = restWrite(...)` 的 `await` 丢了，拿 id 拿到 undefined。
   - 修复：5 处补 await + 全部加按唯一键回查兜底；孤儿单 PO_20260912001/002 留库备查。
   - 沉淀：**正则批量改代码必须复核 await 语义**；"拿 id"场景统一走 restQuery 兜底。

6. **拼音测试单事故**（9/12，用户发现："里面怎么全是拼音"）
   - 根因：Git Bash curl 直接发中文 = GBK 编码乱码入库。
   - 沉淀：**测试体必须 UTF-8 文件方式（`printf` 写文件 + `--data-binary @file`）或 MCP 数据库层**；已两次踩坑。

7. **UTC 时区差一天**（9/11→9/12 修两轮）
   - 现象：北京时间 0-8 点，"今天"的订单对不上。
   - 根因：`toISOString()` 是 UTC。
   - 沉淀：**一切"今天"用 `localToday()`**（services.js 导出全局用）。

8. **分拣屏被并行窗口回滚**（9/12）
   - 现象：上一轮 SortBoard.vue 重构（缺货卡片常驻 / 完成面板 / 二次确认）丢失，文件回到旧版。
   - 修复：整文件重写并发版，交互大改版全部恢复。
   - 沉淀：**多窗口并行，改共享文件前必读磁盘最新版 + git diff**；services.js / SmartEntry / MainLayout / SortBoard 是热点文件。

9. **同声传译插件关闭**（9/12，方案级转折）
   - 现象：小程序后台添加同声传译插件被拒："类目不符合或主体类型不符合"。
   - 排查：个人主体类目库收窄，拿不到与插件匹配的 IT 类类目。
   - 决策：切备选方案 B——自建链路（录音 → 云函数 → 腾讯云 ASR），**比插件方案依赖更少**，已上线。
   - 沉淀：个人主体小程序的能力边界要提前验证，别把方案押在插件上。

10. **TC3 签名 SignatureFailure**（9/12 深夜）
    - 现象：手写腾讯云 TC3 签名总报鉴权失败。
    - 根因：canonicalHeaders 自带尾换行后，还需再接一个分隔换行（官方数组 join 写法自带双换行）。
    - 沉淀：照抄官方 join 写法，别"优化"拼接逻辑。

11. **体验版授权用户配额 3 用尽**（9/12）
    - 现象：建第 4 个测试账号报配额错。
    - 决策：不硬扩，改用内置 administrator 当全功能测试号（改密 + 补 admin_user 映射）。

12. **GLM 并发限流 1302**（9/11）
    - 现象：12 个并发代理批量测试触发限流。
    - 沉淀：压到 1-2 个并发；批量测试排队跑。

## 四、决策记录（为什么这么做）

| # | 决策 | 理由 |
|---|---|---|
| 1 | **商城不做自助注册 / 找回密码** | B2B 客户线下谈、账号绑定一客一价体系；自助注册威胁报价安全。平台 501 拒纯用户名注册、短信通道未配。开号 / 重置走管理员 30 秒；后台自助开号排期 T2.13 |
| 2 | **密码规则 = 名字首字母大写 + 小写 + 数字** | 平台强制 ≥3 类字符；此格式最简且好记（TempPwd000 格式），子账号统一 `TempPwd000` 式 |
| 3 | **语音开单走方案 B（自建 ASR 链）** | 同声传译插件对个人主体关闭；自建链少一个第三方依赖，一句话识别有免费额度 |
| 4 | **个人主体先行，后期换企业** | 用户决策"先跑起来"；届时两条路：主体变更保留 AppID，或换新壳（代码在手迁移零成本）。个人主体不能接微信支付，营业收款不受影响（线下收款） |
| 5 | **菜单按账号屏蔽而非全局** | merchant_a 隐藏库存 / 采购（营业号求简），administrator 测试号全功能；实现键 = 用户名数组 `HIDE_MODULES_FOR` |
| 6 | **写调用全走网关 REST，读保持 js-sdk** | 本环境 js-sdk 写链路多轮实证不可靠（静默 0 行），网关 REST 100% 可靠 |
| 7 | **测试数据清零，等真实数据开业** | 9/12 价格 / 订单 / 流水全清；商品 8 / 客户 5 保留供演练；正式营业前用 Excel 导入真实商品 + 客户清单 |
| 8 | **git 基线 + 每改必提交** | 双窗口并行覆盖事故（分拣屏回滚）后立规矩：v1.0 基线起，冲突可 diff / 回滚 |
| 9 | **识别结果必过人工确认** | 手写单实测 ≈7 成（deepseek-flash 视觉上限），打印单 100%；所有识别产物一律进确认弹窗 / 待核对列表，不直接落单 |
| 10 | **小程序暂不提审** | 备案未过提审必卡；B2B 场景体验版长期够用（客户 = 体验成员扫码）；提审时机 = 备案通过 + 稳定运行后 |
