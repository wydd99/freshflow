## 一、产品定位（2026-09-10 定版）

**首发部署对象=商家A（本地蔬菜批发配送商，即演示视频买方）；终局=白牌多租户 SaaS 卖同行。**
架构后果：数据模型**原生多租户**（全表 tenant_id + tenant 表含商城名/系统名/主题等白牌配置），首发只有一个租户，卖同行时"加租户即开张"，无需改表。
给商家A做：商家小程序下单/后台代客录单（语音、拍照、手写、Excel、文本粘贴五种输入）→ 订单池（草单→确认）→ **采购（计划自动汇总+采购中心，9/10 追加）** → 分拣改重 → 打印（配货单/出库单/标签/送货单）→ 对账结算（一客一价、账期锁单、日报表）。
**不做**：采购对账、供应商入驻、营销、溯源、CRM、进销存全集（对应鲜橙¥2980档以上功能）；**采购计划与采购中心已列入 P2**（9/10 用户追加，基础功能口径=订单聚合采购清单+采购单管理，不含按供应商自动拆单）。

## 二、技术选型（已定，执行中遇方案级岔路再停下确认）

| 层 | 选型 | 理由 |
|---|---|---|
| 后台前端 | Vue3 + Vite + Element Plus + Pinia | 对标鲜橙形态；生态成熟 |
| 商城端 | 微信原生小程序 | 商家只用微信；无需应用市场 |
| 后端 | 腾讯 CloudBase：云函数 + **PostgreSQL** + 云托管（容器） | 环境现成（工具链已接入）；报表/对账需要 SQL；云托管容器跑 FunASR-onnx 做语音识别 |
| AI 能力 | 结构化/图片识别=**GLM-4.5V**（效果优先：用最强视觉档+候选纠错 UI）；**语音=融合案（9/10 定版）**：小程序端=微信同声传译插件（客户语音下单），后台/网页端=云托管 FunASR paraformer-large 容器（商家A团队电脑语音开单）；两端互为兜底 | 效果质量优先：不为省钱降档，取最准引擎 |
| 打印 | P1=浏览器打印 CSS（A4 配货单/出库单/小票，零依赖最快验收）；P2=**云打印薄代理**（分拣完自动出单/标签的无人值守场景）+ ESC/POS 标签机 + 串口电子秤（Web Serial→本地桥备选） | 自动打印是买方"一点一贴"体验的组成部分，P2 落地 |
| 部署 | 后台=CloudBase 静态托管；小程序=微信开发者工具上传 | — |

## 五、风险与对策

1. **范围失控**（最大）：只做 REQS.md 清单内功能，清单外一律进 P3 备选池。
2. 潦草手写识别率：首期承诺"肉眼可辨认字"；配候选纠错 + 未匹配商品一键建档 + Excel 兜底；P1 末用真实单据做 3-5 张小样实测。
3. 电子秤/标签机型号杂：P2 锁定 1-2 个型号先通，其余手输兜底。
4. GLM 并发限流：智能录单走队列+重试；关键路径（手工录单）不依赖 AI。
5. 数据合规：客户报价体系是核心资产 → PG 开启行级权限 + 后台操作日志。

## 六、账号自助能力路线图（9/11 追加）

背景：密码重置必须经过一层身份验证（平台规定：纯用户名密码账号不能自助注册/找回；无验证的重置入口=知道用户名就能冒充任何人）。自助程度随验证通道逐级放开：

| 阶段 | 店家（饭店/食堂）忘密码 | 菜贩子忘密码 |
|---|---|---|
| **现在（v1）** | 找菜贩子 → 菜贩子找运维重置（秒级） | 找运维 |
| **管理边界完成**（T2.13，P2 后段） | **找菜贩子：后台客户管理页一键重置** | 找运维 |
| **配短信通道后**（T3.5，正式版） | 登录页"忘记密码"→手机验证码**完全自助** | 同左 |

配套原则：
1. 登录状态下"修改自己密码"（知道旧密码）随时可做（T2.12：后台设置页 + 商城），不受路线图限制；
2. 重置**他人**密码属于管理动作，必须落在服务端特权（管理边界云函数）或验证通道（短信）上，绝不放浏览器直连入口。
